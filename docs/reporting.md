# Reporting

The framework generates **five reporting artifacts** on every test run, automatically wired through `pytest.ini` `addopts` and the reporting layer in `src/reports/`.

---

## 1. Artifacts at a Glance

| Artifact | Path | Producer |
|----------|------|----------|
| Enterprise analytics dashboard | `reports/dashboard.html` | `EnterpriseDashboardBuilder` |
| Self-contained HTML report | `reports/html/report.html` | pytest-html (`--html ... --self-contained-html`) |
| JUnit XML (CI) | `reports/junit/results.xml` | pytest (`--junitxml`) |
| Allure telemetry | `reports/allure-results/` | allure-pytest (`--alluredir`) |
| JSON execution telemetry | `reports/executions/EXEC-*.json` | `JSONExporter` |
| Latest-run pointer | `reports/latest_execution.json` | `JSONExporter` |
| History index | `reports/history_index.json` | `JSONExporter` |

`pytest.ini` `addopts` automatically enable pytest-html, JUnit XML, and Allure on every run — no extra flags needed.

---

## 2. Enterprise Dashboard (`reports/dashboard.html`)

Generated by `EnterpriseDashboardBuilder` (`src/reports/enterprise_dashboard.py`) at session end. It is a **standalone single-file** dashboard (inline CSS/JS + Chart.js via CDN) containing:

- **KPI cards** — total tests, passed, failed, skipped, execution duration, success rate
- **Charts** (Chart.js):
  - Pass/Fail doughnut
  - Execution timeline
  - Test distribution by module
  - Duration per test
  - Browser distribution
  - Success gauge
- **Results table** — searchable, sortable, paginated, with status & module filters
- **Evidence viewer** — failure screenshots and log code viewer
- **Export** — PDF, Excel, CSV buttons
- **Metadata panel** — environment, browser, framework version, execution timestamp

### How it is triggered

- A `pytest_runtest_logreport` hook in `conftest.py` aggregates results (including xdist workers) and invokes dashboard generation at session finish.
- In non-xdist runs the same hook writes JSON telemetry.

---

## 3. HTML Report (`reports/html/report.html`)

- Self-contained (single file, works offline).
- Includes test metadata, per-test results, and **embedded failure screenshots**.
- Produced automatically by `--html=reports/html/report.html --self-contained-html` in `addopts`.

Open directly:

```bash
start reports/html/report.html   # Windows
open reports/html/report.html    # macOS
```

---

## 4. JUnit XML (`reports/junit/results.xml`)

- Standard JUnit format consumed by Jenkins, GitHub Actions, and other CI tools.
- Automatically produced by `--junitxml=reports/junit/results.xml`.

Jenkins consumption: see [jenkins.md](jenkins.md).

---

## 5. Allure

The framework writes Allure telemetry to `reports/allure-results/` on every run via `--alluredir=reports/allure-results`.

### Viewing the Allure report

Allure results require the **Allure CLI** (installed separately — the Python `allure-pytest` package does not include the CLI):

```bash
allure serve reports/allure-results
```

Or generate a static site:

```bash
allure generate reports/allure-results -o reports/allure-report --clean
```

> `allure-report` is not created by pytest automatically — it only exists after `allure generate`. The `reports/allure-results/` directory is committed as telemetry input, not as rendered HTML.

---

## 6. JSON Telemetry (`reports/executions/`)

`JSONExporter` (`src/reports/json_exporter.py`) writes normalized execution data:

- `reports/executions/EXEC-<timestamp>.json` — full execution record (results, failures, environment, browser, metrics)
- `reports/latest_execution.json` — pointer to the most recent execution
- `reports/history_index.json` — index of past executions for trend analysis

### Secret masking

`JSONExporter._mask_secrets()` replaces sensitive values (passwords, tokens, credentials) with `***REDACTED***` before writing — **no secrets ever reach the telemetry files**.

---

## 7. Report Metadata (`ReportManager`)

`src/reports/report_manager.py` exposes:

- Framework version (`2.5.0-Enterprise`)
- Environment metadata (OS, Python, browser)
- Dashboard resource attachment (CSS/JS)
- Report emission helpers

The dashboard and JSON exporter both read from the same metadata to stay consistent.

---

## 8. Failure Screenshots

On test failure, `Screenshot.capture()` (`src/utils/screenshot.py`):

1. Saves a PNG to `screenshots/failures/<test_name>_<timestamp>.png`.
2. Returns a base64 preview embedded into the HTML report.
3. (Allure) attaches the screenshot to the failed case automatically.

---

## 9. Reading the Results

| Indicator | Meaning |
|-----------|---------|
| `passed` | Test asserted successfully |
| `failed` | An assertion or expected state failed |
| `skipped` | Test skipped (e.g., conditional skip) |
| `error` | Exception during setup/teardown or execution |

The dashboard KPI cards aggregate these counts, and the JSON `ExecutionSummary` stores the same numbers for machine consumption.

---

## 10. Customizing Reports

- **Dashboard**: edit `src/reports/enterprise_dashboard.py` (charts, KPIs, table columns) and `src/reports/report_manager.py` (metadata, assets).
- **HTML**: styling comes from pytest-html CSS; extend via `pytest_html` hooks in `conftest.py` if needed.
- **JSON**: extend `JSONExporter` / `execution_models.py` dataclasses.

All reporting code lives in `src/reports/` and `src/models/execution_models.py`; the pytest wiring lives in `conftest.py`.
